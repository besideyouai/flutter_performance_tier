Android report loop 架构主线

一句话目标：为 flutter_performance_tier 建立可验证的 Android 性能报告闭环架构。

整体架构主视图

一条主线、五层责任、三组合同。

当前方向应该继续收束为 Android-first 本地 report loop：设备侧只生成并私有保存单个 V1 report，主机侧只拉回同一个 report 做 gate、evidence 和 validator；上传、聚合、dashboard 和发布态都放到这个闭环被真机证据证明之后。

当前状态：active，不能关闭 本地合同链路已能验证；还缺真实 Android report、analyzer gate PASS 和填好后的 evidence validator PASS。

缺口 唯一关闭缺口是真机 evidence。 下一步不是继续扩功能，而是由真实 Android 设备跑完整链路并补齐 PASS evidence。

数据流

1

采集信号

Android plugin 通过 collectDeviceSignals 提供设备与运行时信号。

2

生成决策

Dart engine 输出 TierDecision，包含 tier、confidence、reasons、policies 和 signal snapshot。

3

封装报告

Dart service 生成 V1 flutter_performance_tier.performance_report，附带 source、时间和 metadata。

4

设备落盘

Android native 写入 app-private report 目录，并返回 fileName、relativePath、bytes。

5

主机分析

adb 拉取 JSON 后，analyzer 输出 session CSV、结构化日志、parse issue 结果，以及包含 Gate Summary、report / signal 表格、字段核对和 identity checklist 的 android_report_gate.md。

运行链路可写

Dart service 生成当前 V1 report，Android native 写入 app-private files/performance_tier_reports/，MethodChannel metadata 不得 malformed。

主机 gate 可判定

analyzer 只接受当前 V1 Android report，并输出 Gate Summary、Performance Reports、Android Signals、Report Field Check 和 Identity Checklist。
